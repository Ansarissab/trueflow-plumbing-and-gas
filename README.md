# Moral Service — Homepage Redesign (Design 1, "The Rate Card")

A one-page redesign of moralservice.com.au built in [Astro](https://astro.build).
**Only the homepage is authored.** Every other route is the untouched, verbatim
static copy of the live site (HTTrack capture) served from `public/`, so all
existing URLs keep working exactly as they do today.

## The design in one paragraph

The site's real sales story is *know the price before any work starts*. Design 1
is built around that: a conversion arc of Hero → Trust strip → Services →
Values → Owners → Real work → Reviews → **Process + Rate card** → Service areas →
FAQ → Quote form, mobile-first, with the sticky rate card ($0 free fixed quote /
$88 diagnosis credited within 14 days / $165/hr inc GST in 15-minute blocks) and
a call-first sticky mobile bar. All copy is real brand copy: sections reuse the
site's own verified wording, photos, licence numbers, reviews and FAQ — no
invented facts anywhere.

## Build & run

```bash
# Node lives in /usr/local/bin on this machine, not on the default PATH
export PATH=/usr/local/bin:$PATH
cd moralservice-site

npm install          # once
npm run build        # -> dist/  (static, ~10 html routes: 1 home + 9 mirror)
npm run preview      # serve dist/ locally

# dev (authored source only)
npm run dev
```

The preview server serves the copied subpages by full path
(`/about/index.html`, not `/about/`) — pretty-URL mapping is the host's job,
exactly as with the current static site.

## What's authored vs. mirror

| Path | Source |
| --- | --- |
| `src/` (all of it) | **New code** — Astro components, styles, form script |
| `public/` root `index.html` | none — homepage is generated by Astro |
| `public/**` everything else | Verbatim copy of the HTTrack capture (`../moralservice.com.au/`) |

The only build rule to remember: **never edit files under `public/`'s mirrored
subpages** — they exist so the untouched routes keep byte-identical URLs,
anchors, assets and behaviour (including their own CSS/JS bundles under
`_astro/`).

## Homepage composition

`src/pages/index.astro` composes, in order:

`Header · Hero · TrustStrip · Services · WhyMoral · Brothers · WorkGallery · Reviews · ProcessSteps (+sticky rate card) · ServiceAreas · Faq · FinalCta (#quote form) · Footer · MobileContactBar`

### Anchor preservation

The live homepage exposes these in-page anchors; all are kept (and shown in the
header nav / mobile menu):

`#services` `#about` `#why` `#work` `#reviews` `#locations` `#faq` `#quote`

(`#quote` is the quote form thanks to the `FinalCta` section; `#process` is the
merged process + rate card section.)

### Conversion features

- **Rate card** rendered beside the 4-step process, with "Get my quote" jump.
- **Mobile sticky contact bar** (call 1300 522 107 primary / "Get a quote" jump).
- `tel:` links throughout; emergency call-outs noted where the brand states them.
- Trade preselect: "Request a plumbing / electrical quote" links carry
  `data-preselect-service` and set the form's service select before jumping
  (same behaviour as the live homepage).
- Reviews: 4 verbatim Google reviews + the verified "4.9 from 149 Google reviews".
- FAQ: 7 items verbatim; rendered on-page **and** used to generate the
  FAQPage JSON-LD from the same array in `index.astro` (single source of truth).

### Quote form contract (unchanged)

`src/scripts/quote-form.ts` is a faithful transcription of the live site's own
bundle (`public/_astro/PlumbProcess.…B-8Onm6k.js`):

- POSTs to `https://moralservice-form-worker.lachlan-8db.workers.dev/submit`
- `page` = current pathname; `submission_id` (uuid) added only when photos are
  attached; urlencoded body otherwise
- photos: max 5, ≤10 MB, JPEG/PNG/WebP/HEIC — with the exact live error strings
- Cloudflare Turnstile (sitekey `0x4AAAAAAETmVAgqQEFhnLI9`) rendered **lazily on
  first form interaction**; token polled before send
- failure paths reproduce the live messaging (send-failure → email fallback;
  verify-failure → refresh advice) and fire the same `form_submit_fail` /
  `form_submit_success` gtag events before redirecting to `/thank-you`

The form keeps the live page's worker-facing field names and required flags, and
AI-agent deterrence note.

## Design system

`src/styles/home.css` holds tokens (ink navy / pearl / royal blue / sun yellow,
Archivo + Inter, hard-shadow "plate" cards) and all section styles. The layout
relies on `overflow-x: clip` on `html/body` (with an `overflow: hidden` fallback
for older browsers) rather than clipping `main`, so sticky side columns keep
working.

## Known gaps / to verify on the real site

- **Turnstile token** — the widget initialises in the sandboxed headless
  browser used for QA, but Cloudflare doesn't grant a token there. The
  verify-failure path was QA'd; submit-with-token must be smoke-tested once on
  a real browser/domain before going live.
- **`/thank-you` page** — not present in the HTTrack capture (only reachable on
  the live server), so it isn't in `public/`; the redirect target is unchanged
  so the live page will be used in production.
- **Email obfuscation** — the live site uses Cloudflare email-protection
  scripts; the homepage shows `contact@moralservice.com.au` as a plain `mailto:`
  (visible to crawlers — remove if that's not wanted).
- **GA4** — measurement ID `G-L5L6CQY9P4` and the `tel_click` / form events are
  wired as on the live site; only the homepage fires the redesigned page's
  events, subpages keep their original scripts untouched.
